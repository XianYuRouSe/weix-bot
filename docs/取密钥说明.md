# 怎么拿到 master key

微信 4.x 的每个 `.db` 都是 SQLCipher 加密的，每把钥匙由同一个 **master key** 加盐派生出来。
本项目的 `setup.py` 负责“拿到 master key 之后的所有事”，**不负责从内存里读 key**。

## 为什么不在项目里实现

- 读进程内存要适配每个微信版本，微信一更新就可能失效；
- 容易被杀毒软件当成恶意行为拦截；
- 这一步已经有成熟的开源项目在做，重复实现没有意义。

## 拿 key 的三条路

1. **用现成开源工具**（推荐）
   搜索 `PyWxDump`、`wechat-dump-rs` 等支持微信 4.x 的项目，按它们的说明运行，得到一串
   64 位十六进制字符串（32 字节）。这类工具只负责读出 key，不碰你的聊天内容。

2. **已经生成过 `all_keys.json` 的机器**
   换电脑时不用重新取 key，直接：

   ```bat
   首次配置.bat --import-keys 旧电脑的all_keys.json
   ```

   注意：`all_keys.json` 里的钥匙是**跟那台机器的微信数据绑定**的，换机后只有连同
   `xwechat_files` 一起拷过去才有意义；不同人的账号之间不通用。

3. **手工输入**
   如果你手上已经有一串 key（比如从别的工具复制出来的），向导里直接粘贴即可，
   支持带 `0x` 前缀、带空格。

## 格式

- 必须是 **64 位十六进制**，即 32 字节，例如 `0123456789abcdef...`（共 64 个字符）；
- 不要带引号、不要带换行；
- 输错时向导会报“所有库都校验失败”，不会写坏配置。

## 向导会怎么用它

1. 对 `db_storage` 下每个 `.db` 取前 16 字节作为 salt；
2. 按 `PBKDF2(master, salt, 迭代次数, 32)` 派生该库的密钥；
3. 用 page 1 的 HMAC 校验（`wcdb.verify_key`），通过才记录；
4. 全部写进 `config/all_keys.json`。

不同微信版本的迭代次数有差异，向导会自动试几组常见参数（SHA512/256000、64000、4096，
SHA256/256000、64000），哪组能通过校验就用哪组。

## 安全提醒

- master key 等价于**你全部聊天记录的明文**，别发微信、别贴到网上、别提交到 Git；
- 用完记得删掉临时文件；
- 如果 key 泄露，理论上任何拿到 `xwechat_files` 的人都能解密，建议尽快改微信密码并检查设备。
